# ClauseWise: Antigravity Rules

## What this project is
An AI legal document copilot for the Google Virtual Promptwars contest, vertical: AI for Legal Assistance & Access. Full spec: ClauseWise_PRD.md. Full build plan: ClauseWise_Antigravity_Prompts.md.

## Tech stack
- Frontend: React, Vite, TypeScript, Tailwind CSS, shadcn/ui
- Backend: Node.js, Express, TypeScript
- AI: Gemini API only, accessed exclusively through backend/src/services/geminiClient.ts
- No database. No persistent storage of uploaded documents by default.

## Hard constraints, never violate these
- Never create a new git branch. Commit directly to main. The contest requires a single-branch repository.
- Never commit .env, an API key, or any secret. .env.example only, with placeholder values.
- Never write uploaded document text or user questions to disk, a database, or a log file.
- Never call the Gemini SDK from anywhere except backend/src/services/geminiClient.ts.
- Never inline a prompt template inside a route handler. Every prompt template lives in backend/src/prompts/.
- Never draft a new binding legal document. This app explains and analyzes existing ones only, it does not generate contracts.
- Validate every LLM structured-output response against its schema (zod) before using it.

## Standards to hold on every task
- Accessibility: WCAG 2.1 AA. Keyboard operable, labeled inputs, no color-only signaling, prefer shadcn/ui primitives over hand-rolled interactive components.
- Security: validate all inputs, rate-limit public endpoints, never leak stack traces to the client.
- Testing: unit test pure logic, mock the Gemini client in all automated tests, no real API calls in CI.
- Code: TypeScript strict mode, ESLint and Prettier clean, small named functions, no magic numbers.

## Frontend design source of truth
- PRODUCT.md and DESIGN.md are generated by the Impeccable skill (`/impeccable init`, then `/impeccable shape` or `/impeccable craft` for each surface), not hand-authored. Once they exist, treat them as the source of truth for audience, positioning, palette, type, and spacing, do not override them with ad hoc choices mid-task.
- Severity indicators still need a text label alongside color no matter what DESIGN.md's palette suggests, that accessibility requirement overrides general design guidance.

## Repo hygiene
- Keep the repo under 10 MB. Never commit node_modules, dist, build output, or binary sample files.
- Reference clause data lives in reference-clauses/, sample docs in sample-documents/, both small text or JSON only.
